# M0: charge the fixed complete fixture snapshot to its parent job

Build on PR98, main eventual integration baseline. The complete indexed payload mode already validates a six-object native snapshot (parent/root directories, owner journal, payload, registry database and lease), but parent settlement charges only payload. Move that existing read-only snapshot before settlement and charge its observed total once to the same parent admission job. Sample free bytes after the validated snapshot, retain the one admission-start elapsed check, then mark incomplete and confirmed stopped as before. Compare the fixed observation bound only after charging so an over-bound observed value is not silently omitted.

Partial mode retains payload-only observation and charge. Rename private helper/report field to describe observed store bytes rather than payload-only bytes; each report must identify its accounting scope (fixed_six_objects or payload_only). Complete charged bytes equal the six-object observation, not payload plus the six-object total. Keep payload observation separately visible and require total at least payload. No duplicate charge/release/cleanup/completion/schema/public renderer authority changes.

Validate complete report equality with six-object total, partial equality with payload high-water, distinct scope labels, retained charge/refusal/time/duplicate tests. This is a stable before-registry-reopen fixture checkpoint, not lifetime peak or final footprint: later SQLite writes may grow, partial/control/failed-observation paths remain incomplete, reservations stay metadata, no continuous/global owner or production verification is established. No arbitrary filesystem walk, user-file deletion, release or milestone completion.
