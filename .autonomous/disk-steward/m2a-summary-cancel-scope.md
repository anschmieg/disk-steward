# Cooperative cancellation for bounded subtree summaries

From durable PR1197a40f71/main eventual baseline. Each summary request carries a unique typed summary-attempt ID in addition to exact observation ID. Backend registers one active cancellation flag before spawning work, owns it with RAII and releases on success/error/unwind. A separate narrow cancel command accepts only exact active pair and signals an atomic flag without waiting for the session mutex or NativeCheckGuard held by the walk. Stale/absent pairs refuse; no filesystem or generic execution access.

Walker and command check cancellation at cooperative boundaries; canceled work produces no reliable summary receipt and preserves page/cursor/review/source. In-flight filesystem/SQLite/native metadata calls cannot be forcibly interrupted; no hard deadline/pause/resume/durable checkpoint claim. UI exposes cancel only for active summary, disables duplicates, preserves busy ownership until native completion, reports request acknowledgement separately from actual completion, sanitizes errors and ignores late cancel responses from earlier jobs. Unique attempt IDs keep a delayed request from targeting a subsequent UI run on the same observation.

Disposable native tests for exact/stale pairs, registration release and pre-canceled walk; UI deferred-promise tests verify exact cancel pair, retained busy state/page and unconfirmed cancellation. No cleanup eligibility, user-file writes/cache deletion or automatic release. Full M2A/MVP gates remain open; actual MVP followed by adversarial review/fixes/validation and disable-stop remains required.
