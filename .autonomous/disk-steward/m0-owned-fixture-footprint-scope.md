# M0: fixed owned-fixture footprint observation

Add a read-only, complete-payload-only observation after confirmed worker stop and identity-bound payload readback. Measure exactly six task-owned objects: held parent and store directories, owner journal, fixed payload, private registry database, and its lease file. Require strict parent/root entry lists; unexpected entries and SQLite journal/WAL/SHM sidecars refuse observation. No generic walk, caller path, arbitrary file selection or renderer access is introduced.

The registry validates its own held/captured control identities and private metadata, then returns an opaque bounded snapshot of its two control files, including native/logical observed bytes and identities without paths or handles. The store combines it with its four known objects. Require distinct identities, exact private modes/UIDs, regular-file single links, held/named identity agreement, stable metadata before/after (size, native blocks, mode, links, owner, modification/change timestamps), checked arithmetic and cooperative deadlines. Recheck entry lists and journal state. Unknown or changed scope yields no accepted observation.

The complete-payload supervisor requires the same stop receipt, payload binding and reconciliation behavior as before. It compares the six-object snapshot to the fixed 128 KiB value as a separate probe check and reports the byte total and object count. The existing reservation remains payload admission metadata: this observation does not retroactively reserve directory/index overhead or enforce a whole-store quota. Partial and descriptor-only fixtures retain their current scope. Failure retains files and reservation; no cleanup eligibility is added.

Validate with tiny task-owned fixtures: accepted complete case, premature/wrong-receipt refusal, unknown entries and sidecars, unsafe metadata and link/identity replacement, checked totals and expired cooperative checks where testable. Observe current max(logical length, native blocks*512) per distinct object. This is not a lifetime high-water measurement, all filesystem overhead, recovered/free space, allocation atomicity, same-user race immunity, production aggregate accounting, durable byte receipts, OS containment, power-loss, private authentication or milestone acceptance. Tasks0.1/0.3 and R5.8 remain open. Main is eventual integration baseline; branch builds on PR94; version0.0.x/no release.

The report labels the snapshot as before_registry_reopen. Reopening and later SQLite transactions may change control-file size or allocation after the snapshot; the observation is not the final or maximum footprint of the complete probe lifecycle.
