# M0 bounded payload through worker directory capability

Extend PR89 descriptor-only ownership transfer with a separate fixed --run-indexed-store-payload fixture. Retain the pre-spawn128KiB identity-bound reservation; pass only the validated directory via stdin to an exact environment-cleared child. That child writes only the existing deterministic32KiB payload through the shared payload accounting core, with native free-space sampling, 2GiB reserve+1MiB headroom, admission, allocation-aware high-water charging and identity checks before/after chunks and sync. No caller path, data, credential, endpoint or cleanup parameter is accepted.

Avoid a second accounting implementation: refactor the original OwnedStore wrapper around the same root-based private writer with a narrow ownership-verifier closure. The descriptor owner validates exact bound-self journal bytes/identity, directory identity/mode and the fixed payload file. Partial data remains retained after failure and cannot yield readiness. A repeated attempt cannot overwrite an existing payload.

After readiness and exact kill/reap/reader join, the parent requires the matching stop receipt and stopped journal, then performs bounded held-descriptor readback of the exact fixed payload, validates native metadata/identity before and after and reopens its named file. It requires byte equality and high-water usage within the committed reservation. Reopened registry remains NeedsReconciliation/priorStopped with reservation retained; no cleanup is added.

This is an app-owned synthetic worker/store composition probe, not live Git transfer, durable byte receipts, directory/index footprint accounting, OS sandbox/process-tree containment, hard OS latency/RSS bounds, atomicity against same-user interference, credential validation or milestone acceptance. Native platform gates remain explicit.
