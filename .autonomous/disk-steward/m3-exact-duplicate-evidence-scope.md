# D6 selected-file exact comparison evidence

Continue R2.1–R2.4, R3.3 and task 3.2 from PR132, with main as eventual integration baseline. The MVP needs detector-backed evidence beyond metadata. This slice implements an explicit read-only comparison of user-selected regular files on the currently observed folder page. It does not freeze an executable cleanup adapter, select survivors, grant cleanup authority or complete M3/MVP.

No file is selected automatically. Users choose 2–32 observed opaque item IDs and explicitly allow local content reads for that selection before each run. Changing selection clears consent. The typed command rejects paths, metadata supplied by the renderer, stale observation/IDs, duplicate IDs and missing consent. It validates all selected entries before reading any contents: regular files only, no-follow same-volume bindings, current known single links, no hidden/dataless objects, unchanged native per-file observation stamps (including creation/change metadata) and logical sizes, current physical exclusion ancestry and policy. Directory and managed-boundary protections remain in force. A native macOS F_GETPATH/canonical-path identity check refuses recognized managed/system/credential/cloud-store ancestors even through aliases; unsupported platforms refuse content-scope verification. Recognized names are conservative and not complete provider classification or atomic ancestor-relocation isolation.

Bound each file to 16 MiB, selected input to 64 MiB, cumulative actual reads to 192 MiB (including full-hash and byte-comparison rereads), one job, fixed buffers and cooperative five-second checks. Hash entire files with SHA-256, then stream-compare matching size/hash groups byte for byte. Validate retained descriptors, named bindings, metadata, folder scope and unchanged exclusion policy before publishing matching groups. Cancellation targets the exact observation/attempt pair; acknowledgment is a signal, not completion. A blocking filesystem call cannot be forcibly interrupted by this cooperative helper. Known dataless objects are refused; other availability remains unverified, so explicitly selected reads may trigger provider I/O whose traffic is not measured. This limitation is disclosed beside per-attempt consent and is not provider acceptance evidence.

Results retain only bounded local historical evidence in memory: opaque IDs, comparison/version identity, selected-file count, read-byte count and matching groups. No source paths, file contents, digests, uploads or persistent comparison cache are exposed. Content reads can update filesystem access metadata even though the app writes no source contents. Failed or canceled work cannot publish a partial successful comparison. Previous UI evidence remains explicitly historical; new scope replaces it. Matching content does not prove dispensability, unique physical storage, current freshness or safe deletion, including APFS sharing. Existing live plan entries remain blocked.

Validate disposable full-content equal/different/empty files, partial reads, truncation/growth, limits/cancellation/deadlines/I/O errors, hardlinks/symlinks/hidden/managed/excluded/stale selections, metadata replacement and source invariance; UI exact selection/consent/cancellation/result identities and failure preservation. Native/provider/permissions/large-scale/usability gates remain open. M3 still requires two named executable generated/cache families plus exact duplicates through stage/restore/separate purge and controlled recovery. After actual MVP delivery, final adversarial review/fixes/validation and automation disable/stop remain mandatory.
