# Explicit recursive scan checkpoint

Continue R1.1/R1.2/R1.5 from PR130, with main as eventual integration baseline. The product must investigate selected storage scopes and retain honest, editable evidence without cleanup authority. This slice adds an explicit durable restart for an unfinished bounded recursive metadata scan, rather than persisting live descriptors or trusting old totals. It does not complete M2A or the MVP.

At a paused batch boundary, save a private root metadata stamp, exclusion revision, bounded batch/entry counts and SHA-256 fingerprint of the ordered observed metadata transcript. No source path, file contents or replay names are persisted. Store this separately from one-folder paging checkpoints under its own schema/application identity; retain existing checkpoints. Use exact observation/scan IDs and saved-record compare-and-swap. Inspect and forget are explicit; saving again replaces only the expected recursive record. Logical forgetting is not secure erasure.

Resume requires a fresh native folder selection. Verify the full root stamp and physical exclusion ancestry before enumeration. Recreate traversal from the start and require the ordered metadata fingerprint and counts to match within one cooperative two-second deadline before retaining the new cursor. Fresh observation and scan IDs bind future requests. Resume pauses; it does not silently continue. A changed/reordered/unreadable prefix, changed policy, wrong root, corrupt record, deadline or resource uncertainty refuses recovery and preserves the existing session and saved record. Matching metadata is historical evidence, not content identity, an atomic filesystem snapshot, trusted freshness or cleanup approval. Completed subtrees can change after replay passes; ordinary scan limitations remain.

Retain existing 512-entry batches, 65,536-entry total, sixteen directory frames and 15-minute in-memory eligibility; replay can refuse a checkpoint too expensive to revalidate within two seconds. Storage uses private modes, no-follow SQLite access, bounded payload/database sizes and a 2 GiB free-space reserve plus checkpoint headroom. No generic renderer filesystem/SQL/execution capability, source writes, detector eligibility or release is added.

Validate actual disposable nested traversal across restart/store reopen, exact remaining progression and hardlink accounting; altered earlier file metadata, root/policy/fingerprint mismatch and deadline refusal; record CAS/corruption/oversize/privacy; UI save/resume/forget identities and failure preservation. These fixtures do not prove million-item performance, provider behavior, native WebView/accessibility or release acceptance. Actual MVP delivery and final adversarial review/fixes/validation/automation disable remain future gates.
