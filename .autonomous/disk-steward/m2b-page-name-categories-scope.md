# Link current-page name categories to the explorer list

From PR127bccd89a with main as eventual integration baseline. Advance the category/list portion of R6.1 and M2B without claiming a storage map or completing M2A/M2B. Native code derives a closed category from the raw name suffix and native entry kind during the existing bounded page observation: image, document, archive, media, code/data, other file names, folders, symbolic links, other kinds and unreadable entries. Extension matching is ASCII case-insensitive; non-UTF8 suffixes or unknown extensions remain otherFile. A non-UTF8 name prefix can still have a recognized ASCII suffix. Names are hints, never content identification or safe-removal evidence.

Build fixed-order native aggregates over at most 512 current-page entries with exact checked u64 logical-byte totals serialized as decimal strings, entry counts and separate unknown-size counts. Hard links count per name, not per unique file object. Report no aggregate allocated/reclaimable bytes. Classify folders/links/special entries by native kind even when their suffix resembles a file extension. Add no source access, file-content reads, path exposure, persistence/schema changes, import eligibility or execution authority.

Display the whole-page category baseline with keyboard-accessible pressed filter buttons linked to the existing list. Text search combines with the category filter. Sorting/filtering do not change aggregate values, size-bar denominator, selected evidence or whole-page import semantics. Successful observation replacement resets the category filter; failed refresh preserves it. Unsupported/missing aggregate data does not invent zeros.

Validate disposable native mixed-name/kind fixtures, exact hard-link per-name totals/unknowns/overflow and serialization; UI filter/search/sort, exact values beyond JavaScript safe integers, selected evidence, unchanged whole-page import disclosure, and failed-refresh preservation. Native WebView/VoiceOver, rich map geometry/shared map selection, complete type/content classification, large-tree performance, durable recursive recovery and broader MVP gates remain open. Actual MVP completion still requires final adversarial review/fixes/validation followed by automation disable and stop.

Validation note: the initial native fixture attempted an invalid UTF-8 filename and this macOS filesystem returned Illegal byte sequence. Classification of invalid suffix bytes and a non-UTF8 prefix with a recognized suffix is tested directly on raw byte slices instead; no claim is made that APFS accepted those names. The frontend regression initially used incorrect heading/search roles; its queries were corrected to the actual evidence region and searchbox. Final suites pass.
