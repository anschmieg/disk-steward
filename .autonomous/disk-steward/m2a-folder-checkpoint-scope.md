# Explicit durable checkpoint for one folder’s paging scan

From durablePR122042738f/main eventual baseline. User-facing save/resume/forget for a stable incomplete immediate-folder page. No automatic persistence of source names. One private versioned SQLite row stores native directory stamp (dev/inode/birth where supported/mode/size/nlink/mtime/ctime), ordered raw entry-name prefix, page/count, exact saved exclusion revision and opaque checkpoint ID. No absolute source path/file contents/execution authority. Names remain private; renderer receives only bounded label/page/count/ID.

Save uses exact observation ID plus expected checkpoint ID (CAS), current stable cursor and pre/post held bindings and exclusion checks. Resume requires a fresh native picker selection and exact root stamp, known dataless refusal before open, physical exclusion ancestry, exact exclusion revision and fresh binding revalidation. Independent iterator replays every raw prefix name (dot entries ignored), requiring exact order before reading the next page. Never serialize Dir/cookies or infer saved access authority. Prefix/order/time/metadata/registry uncertainty refuses without replacing old session/checkpoint. Success returns next page with fresh observation IDs and a new root breadcrumb; saved progress advances only on another explicit save. Cursor counts remain exact across normal paging. Forget CAS-deletes only the row; no source/user-file operations or secure-erasure claim.

Bounds: existing512entry pages/128page cap/2sec cooperative native metadata/replay checks, max65536 prefix names<=255bytes,16MiB JSON,32MiB DB, DELETE journal/FULL sync,500ms SQLite busy timeout,2GiB+64MiB free reserve before checkpoint writes. Private0700directory/0600one-linkDB, nofollow open, journal validation/no symlink or hardlink redirection, unknown schema/corrupt/oversized rows fail closed and retain evidence. No user cache removal. Large prefixes or legitimate filesystem reordering may refuse resume; old checkpoint can be inspected/replaced explicitly. No recursive/million-item/performance/power-loss/Windows/provider/nativeWebView acceptance; fullR1.5/M2A/MVP remain open.

Validate disposable store-reopen+resume composition, later-page replay without omissions/duplicates, stale CAS/root/prefix/membership/version/corrupt/oversize/privatefile/lowspace cases, typed command rejection and frontend deferred operations. No cleanup eligibility. Actual MVP then final adversarial review/fixes/validation and automation disable-stop remain mandatory.
