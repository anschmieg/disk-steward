# M0: live incomplete latch on admitted indexed-worker errors

Build on PR102, main eventual baseline. Once coordinated admission succeeds, any later launch/bind/readiness/supervision/inspection/accounting error while the original registry remains leased must attempt a conservative live NeedsReconciliation latch. Read actual row state, validate exact admitted ID/native identities/reserved bytes, then latch Registered/Active/Stopped with its actual prior state; validate existing NeedsReconciliation only with an allowed prior state. Refuse missing/replaced/mismatched/completed/cleanup states without modifying them. Preserve the original error and append a sanitized latch failure if recording could not be established.

Use a private explicit Result closure/finalizer, not a Drop that cannot report errors. Keep the leased registry in an Option through the admitted operation and pass its slot to the closure. Existing successful paths drop/take it only after their validated live latch and before reopen. Errors after that deliberate close keep the original error and do not reacquire/retry a possibly unsafe control path: the preceding latch is already required by control flow. Add no claim that the fallback confirmed worker stop, reader join, allocation or cleanup. Existing stop helpers/receipts and budget settlement remain unchanged; no synthetic zero charge or stop acknowledgement on uncertainty.

Tests use disposable fixed control registries and injected Result errors, covering Registered/Active/Stopped actual states, already-latched replay, exact identity/reservation preservation, immediate growth refusal, mismatch/missing refusal and original error retention. No real OS timing races, source repositories, new CLI modes, generic renderer capabilities, schema, cleanup, capacity release or milestone completion. Version0.0.x/no releases. Power-loss/global owner/continuous limits/private authentication/platform gates remain open.
