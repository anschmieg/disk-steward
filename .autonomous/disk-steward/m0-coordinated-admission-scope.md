# M0: coordinate budget preflight and durable store admission

Add a small backend-only verification-admission crate that composes the existing BudgetController and VerificationStoreRegistry. It accepts an already registered, fresh store identity: state Registered, no prior state, and zero existing reservation. Reject missing/invalid/nonfresh/already-reserved stores and invalid requested amounts before starting a budget job; do not adopt, resume or grow an existing attempt.

Start the local budget slot, preflight the entire requested reservation against per-repository/aggregate/free-space limits, then commit the registry reservation using expected current zero. Return the job ID and committed metadata only after both checks succeed. The result grants no filesystem or execution capability. No worker launch, network request, lifecycle advancement, schema change, cleanup or capacity release occurs in the helper.

Preserve the original typed refusal and retained local job history. A pre-handoff failure known to have made no durable mutation may fail the local job and acknowledge that this helper launched no worker, without confirming cleanup. An ambiguous registry storage/path/schema failure must retain the local slot as incomplete and return no successful result; never retry or erase the reservation. Bound coordinated admission history to 4,096 retained budget jobs through a read-only count accessor, including failed and completed jobs, with no pruning/reset. The standalone budget primitive's separate historical-cap PR remains independent.

Integrate the fixed indexed worker parent after trusted native identity registration: sample free bytes through its validated owned directory handle, use the helper before journal binding or descriptor handoff, and check the committed record and running local job. Existing post-handoff stop/readback/reconciliation behavior stays unchanged. Root/control creation already precedes this check; it is pre-payload admission, not a claim that initial directory/index creation was admitted. The parent admission budget does not replace child runtime accounting or become an app-wide owner.

Validate committed success, low-space and proposed-growth refusal without row mutation, retained/global reservation and reconciliation refusal, nonfresh/malformed requests, local concurrency, bounded history, and conservative failure settlement. Use only private disposable control fixtures and simulated numeric large totals; allocate no GiB files. Tasks0.1/0.3 and R5.8 remain open: trusted free-space observations can become stale, SQLite is metadata admission rather than a byte quota, and cross-process/global observed usage, whole-store peaks, OS containment, private authentication, power-loss, cleanup and milestone acceptance remain unproved. Main remains eventual integration baseline; branch builds on PR95; version0.0.x/no release.
