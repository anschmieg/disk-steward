# M0: settle parent accounting after fixed worker payload observation

Build on PR96, with main as eventual integration baseline. For the existing complete and partial disposable payload modes only, after exact child stop/reap, reader join, receipt and native identity/content validation, charge the observed payload allocation high water into the same parent budget job used for admission. Sample free space through the owned directory capability. Mark the attempt StoreIncomplete and acknowledge confirmed worker stop, retaining measured bytes and the durable reservation. Neither mode establishes remote verification success; do not complete the budget job, confirm cleanup, release capacity, retry or grant cleanup authority.

A private probe helper accepts numeric observations from the already validated caller, rejects reused/nonfresh local jobs before charging, charges before settling, preserves any budget refusal reason and bytes, and acknowledges stop even on an observed numeric budget refusal. A failed native observation or free-space sample does not invent a zero observation or issue settlement. Descriptor-only and stall modes stay outside this payload observation scope.

Tests cover complete and partial parent reports, nonzero retained charge matching validated payload observation, free-space/overshoot refusal with retained usage and original failure reason, and duplicate settlement refusal without double charging. This is payload-only accounting at a stopped checkpoint: directory/journal/SQLite bytes and earlier peaks remain unaccounted, SQLite reservations remain metadata, and there is no global owner, continuous parent monitor, OS containment, production Git, power-loss or milestone completion claim. Version stays 0.0.x; no releases or user-file deletion.
