# M0: retain explicit incomplete budget state on admitted errors

Build on PR109 with main as eventual baseline. Indexed fixture attempts already finalize their leased registry on errors, but an error before parent accounting can leave the same admitted BudgetController job Running until the probe returns. Add a private Result finalizer around the existing guarded attempt result.

On Err and an exact known Running job, transition to Failed(StoreIncomplete,worker_stopped=false), retaining ID, ingress/store usage and occupied concurrency slot. Preserve the original error. Existing Failed jobs and Canceled jobs without cleanup confirmation retain their exact first reason, stopped state and usage. Do not acknowledge stop, zero charges, confirm cleanup, create jobs, reset deadlines or touch durable reservations. Unknown jobs, Completed jobs, or cleanup-confirmed Canceled states must stay unchanged and append a sanitized failure-to-establish-incomplete-state message to the original error. Ok results remain unchanged.

The helper is private to fixed indexed probe flow and runs after its existing registry finalizer; no renderer/public API, generic execution, source/user-file operations or new CLI mode. Use pure-controller deterministic tests for late error before/after usage, existing resource refusal/cancellation/stopped states, replay, slot retention/retry refusal, success, unknown/completed refusal and unchanged usage. Root reviews integration before native tests/strict Clippy/fmt/version. No hard OS/global owner/private authentication/power-loss/cleanup/M0 acceptance claim; keep0.0.x/no release.
